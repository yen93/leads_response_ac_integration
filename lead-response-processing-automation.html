Lead Response Processing Automation

Per-reply ActiveCampaign notes and AI stage changes

When a sales lead replies to one of James's outbound follow-ups, this automation acts on that reply automatically: it records the reply, writes a note on the lead's ActiveCampaign deal summarising what they said, and lets an AI model decide whether the deal should move to a new sales stage. It runs quietly in the background, once a minute, inside James's Gmail.

Where it fits in the pipeline

This is the last step in a two-part flow. An upstream automation already watches James's outbound follow-up threads and, the moment a lead replies, moves that thread into a dedicated Gmail label and records the lead's details.

  • Upstream (already running): detects the lead reply, records the lead (email, and its ActiveCampaign contact / account / deal), and files the thread under the label @-sales-to-action-outbound-lead-responses.
  • This automation (new): watches that same label and processes each reply — logging it, adding the deal note, and updating the stage where warranted.

Because the upstream step has already figured out which ActiveCampaign deal the lead belongs to, this step simply reads that link and acts on the right deal.

What it does on each reply

Every minute the automation checks the label for lead replies received in the last 10 minutes. For each new reply it runs these steps in order:

  1. Log the reply. It records one entry per reply message so the same email is never processed twice.
  2. Summarise the message. An OpenAI model reads the reply and produces a short, plain-language summary of what the lead actually said (stripping greetings, signatures and quoted history).
  3. Add a deal note. It posts a note on the lead's ActiveCampaign deal reading "Lead responded with <summary>", followed by a line noting the note was posted through the automation.
  4. Decide on the stage. The AI judges whether the reply means the deal should move to a different sales stage.
  5. Change the stage (only if needed). If a different stage clearly applies, it moves the deal, adds a second note recording the change, and timestamps it. If no change is warranted, the deal stays exactly where it is.

Sales stages the AI can choose from

The AI may only move a deal into one of the following stages, or leave it unchanged:

  • CONTACT MADE - NO REPLY
  • CONTACT MADE - REPLY NO
  • CONTACT MADE - REPLY YES
  • F2F / SALES DEMO BOOKED
  • Missed Deals (Due to Conflict of Schedule, When Schedules Collide)
  • Unqualified: Interest shown (no needs defined - no budget / dates / event)
  • Qualified: Sent proposal + avails NO AUTOMATION FOLLOWUP
  • DEAL WON: SOW NOT returned - awaiting briefing call, travel etc

If the reply doesn't clearly fit any of these, or already matches the deal's current stage, the automation makes no change — it only ever moves a deal when there's a clear reason to.

What it records

Each processed reply produces one tracked entry, holding:

  • A link to the lead it belongs to.
  • The Gmail message identifier — used to guarantee a reply is handled only once.
  • The time the deal note was added.
  • The time the stage was changed (left blank when no change was made).

These timestamps make the automation safe to re-run: if a step doesn't complete, the next pass picks up where it left off rather than duplicating work.

Reliability and safeguards

  • No duplicates. Each reply message is processed once; repeats are skipped.
  • Only genuine lead replies. James's own follow-ups and automated bounce / system messages are ignored — only external replies from the lead trigger action.
  • Safe retries. If ActiveCampaign, the AI, or the database is briefly unavailable, the reply is simply retried on a later run; nothing is lost.
  • One run at a time. A lock prevents overlapping runs from stepping on each other.

Running costs

The one-minute schedule itself is free. Gmail, the scheduling platform, the database, and the ActiveCampaign updates are all either free or already covered by existing subscriptions.

The only usage-based cost is the OpenAI summary, billed per lead reply — a fraction of a cent each — not per minute. Runs where no new reply has arrived cost nothing. In practice the cost tracks how many leads reply, not how often the automation checks.
